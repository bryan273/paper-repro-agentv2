How it works

  1. ReaderReads the PDF and writes a claim contract: the number to check, where it is, a tolerance fixed before any run, what a faithful implementation needs, and every detail the paper leaves open.
  2. RouterChecks what the authors released (full code, partial, or nothing) and whether this machine can run it, including whether a GPU is needed.
  3. PlannerLays out the files, one config, a smoke test and the checks to run before the full experiment.
  4. ImplementerWrites and runs code in a sandbox, alone, until one command re-creates the number. It is never shown the paper's value. A repair manager steps in when it gets stuck.
  5. VerifierDeletes the results, re-runs everything from scratch, searches the code for copied numbers and checks it against the requirements. The verdict comes from that re-run.
