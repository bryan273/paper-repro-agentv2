# Project Summary

Paper Reproduction Agent helps researchers inspect and reproduce machine-learning results reported in academic papers. Its frontend provides a demo dashboard, recorded experiment runs, and a reproduction interface. Researchers can review run timelines, claims, assumptions, verdicts, and supporting evidence.

The project also includes a benchmark archive of recorded runs across papers and model configurations, blog pages, localization, Supabase components, and preserved Python agent and runner reference code. Recorded runs can be viewed without a live reproduction backend.

# Project Module Description

- **Demo dashboard:** Browse demo papers and recorded runs.
- **Run viewer:** Inspect recorded events by stage or timeline, including claims, requirements, assumptions, verdicts, and evidence.
- **Reproduction UI:** Static interface with localization and job-related UI logic.
- **Benchmark archive:** Browse benchmark metadata and recorded JSONL runs through the reproduction interface.
- **Paper viewer:** Open PDFs and access event logs and evidence downloads.
- **Blog:** Render blog indexes and articles from configured routes.
- **Authentication routes:** Display callback and error pages.
- **Shared UI:** Reusable components, layout elements, and mobile and notification hooks.
- **Run-steps function and schema:** Supabase components for run-step processing.
- **Reference agent:** Preserved Python modules for paper processing, search, execution, sandboxing, events, and server functionality.

# Technology Stack

- **Frontend:** React, TypeScript, Vite
- **Styling and UI:** Tailwind CSS and reusable component library
- **Content:** Markdown blog rendering and prerendering utilities
- **Reproduction and benchmark UI:** HTML, JavaScript, CSS, and localization
- **Backend:** Supabase Edge Function and SQL schema
- **Reference backend:** Preserved Python agent and sandbox runner
- **Run data:** Static JSON metadata, JSONL event and benchmark recordings, and PDF documents

# Usage

From `app/frontend/`, install dependencies and start the development server:

```bash
npm install
npm run dev
```

To check and build the frontend:

```bash
npm run lint
npm run build
```

The production build is written to `app/frontend/dist/`. Supplied demo and benchmark runs can be viewed without starting the Python backend; the original Python runner and backend are retained as reference code.
