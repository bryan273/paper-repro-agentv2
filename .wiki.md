# Project Summary

Paper Reproduction Agent helps researchers inspect and reproduce machine-learning results reported in academic papers. Its frontend presents demo experiments and recorded runs, with tools to explore event timelines, papers, claims, assumptions, verdicts, and evidence.

The project includes a reproduction interface, localization support, and a Supabase Edge Function for run steps. The demo dashboard also provides static recordings and does not require a live reproduction backend. The original Python agent and runner remain available as reference code.

# Project Module Description

- **Demo dashboard:** Browse supplied demo papers and recorded runs.
- **Run viewer:** Replay recorded events by stage or timeline and inspect claims, requirements, assumptions, verdicts, and audit evidence.
- **Reproduction UI:** Static frontend assets for the reproduction flow, with localization support.
- **Run-steps function:** Supabase Edge Function for run-step processing.
- **Paper viewer:** Open associated PDFs and access event logs and evidence downloads.
- **Blog:** Render blog indexes and articles from configured routes.
- **Authentication routes:** Provide callback and error pages.
- **Shared UI:** Reusable components, layout elements, and mobile and notification hooks.
- **Reference agent:** Preserved Python modules for paper processing, search, execution, sandboxing, events, and server functionality.

# Technology Stack

- **Frontend:** React, TypeScript, Vite
- **Styling and UI:** Tailwind CSS and reusable component library
- **Content:** Markdown blog rendering and prerendering utilities
- **Reproduction UI:** HTML and JavaScript assets, including localization support
- **Backend function:** Supabase Edge Function
- **Reference backend:** Python agent and sandbox runner from the uploaded source
- **Run data:** Static JSON metadata, JSONL event recordings, and PDF documents

# Usage

From `app/frontend/`:

```bash
npm install
npm run dev
```

To check and build the frontend:

```bash
npm run lint
npm run build
```

The production build is written to `app/frontend/dist/`. Supplied runs can be viewed without starting the Python backend. The original Python runner and backend are retained as reference code.
