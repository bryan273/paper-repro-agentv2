# Project Summary

Paper Reproduction Agent is a research tool for inspecting and reproducing machine-learning results reported in academic papers. Its web frontend lets users browse demo experiments, review recorded run timelines, and inspect papers and evidence.

The frontend supports recorded replays only; it does not run new reproductions or connect to a live AI or sandbox backend. The original Python agent and runner remain as reference code. The interface supports Chinese and English with a remembered language preference.

The research workspace now includes buttons with clearer elevation and restrained semi-dimensional depth, while preserving existing functionality and the bilingual interface.

# Project Module Description

- **Demo dashboard:** Browse demo papers and recorded runs in Chinese or English.
- **Run viewer:** Review recorded events by stage or timeline, including claims, requirements, assumptions, verdicts, and audit evidence.
- **Paper viewer:** Open associated PDFs and access event logs and evidence downloads.
- **Language support:** Shared translations and remembered language preference.
- **Button styling:** Distinguish primary, secondary, toolbar, icon, and language controls with varying elevation, lighting, edge depth, and pressed-state feedback.
- **Blog:** Render blog indexes and articles from configured routes.
- **Authentication routes:** Provide callback and error pages.
- **UI components:** Shared interface components, including accessible dialog controls.
- **Reference agent:** Preserved Python modules for paper processing, search, execution, sandbox, events, and server functionality. They are not connected to the frontend for live runs.

# Technology Stack

- **Frontend:** React, TypeScript, Vite
- **Styling and UI:** Tailwind CSS, reusable components, and custom CSS
- **Localization:** In-app Chinese and English translations with remembered language preference
- **Content:** Markdown blog rendering and prerendering utilities
- **Reference backend:** Python agent and sandbox runner from the uploaded source
- **Run data:** Static JSON metadata, JSONL event recordings, and PDF documents

# Usage

From `app/frontend/`:

```bash
npm install
npm run dev
```

To check and build the frontend:

```bash
npm run lint
npm run build
```

The production build is written to `app/frontend/dist/`. Supplied runs can be viewed without starting the Python backend. Running new reproductions requires the original sandbox runner and backend setup; that functionality is not connected to this frontend.

Button interaction and build checks passed for desktop and mobile widths and both languages. Screenshot capture did not produce an image, so independent visual review remains incomplete. No GitHub push was reported.
